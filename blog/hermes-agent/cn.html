我如何把 Hermes Agent 用作全天候在线的研究与写作助手

我的配置：早上 8 点每日简报、晚上 10 点每日与每周总结、论文写作、写博客，以及用手机远程办公。

Gordon Guocheng Qian
2026 年 5 月 18 日 · 阅读约 7 分钟

我一直把 Hermes Agent 当作围绕我的研究、写作和日常工作流的个人 AI 操作层来使用。

重点不在于它能聊天。能聊天的工具很多。真正有用的地方在于，Hermes 可以作为一个持久运行的 agent 存在，具备记忆、工具、定时任务、文件访问、联网能力和消息平台推送。这让它从一个聊天机器人变成了更接近个人研究助理的东西：可以在后台干活，需要时向我汇报。

我目前的配置有三个主要循环：

  1. 早上 8 点的每日简报，覆盖研究、市场观察和待办事项。
  2. 晚上 10 点的每日总结，回顾我今天做了什么、哪些应该延续到明天。
  3. 一份每周总结，把一周的工作沉淀成更高层次的工作日志。

基本配置

Hermes 在我的 Mac mini 上本地运行，通过以终端为核心的工作流连接我的各种工具。因为这个 agent 就住在存放我本地仓库、论文草稿、笔记和博客文件的那台机器上，一条手机消息可以变成文件系统上的真实工作，而不只是又一条聊天回复。大致架构如下：

Mac / 本地文件系统
        ↓
Hermes Agent CLI + 工具系统
        ↓
网页搜索、文件编辑、终端命令、记忆、会话搜索、定时任务
        ↓
通过飞书/Lark 推送到我的手机

深度工作我用终端版本，尤其是论文编辑和仓库级任务。我还把 Hermes 接入了飞书/Lark，这样定时简报和总结可以直接推送到我的手机上。

这套配置刻意做得很“无聊”：本地文件留在本地，定时任务通过 Hermes cron 运行，消息通过一个普通的聊天应用送达。正是这一点让它真正实用。

定时任务

周期性的自动化由 Hermes cron 任务处理。概念上大致是这样：

上午 8:00   每日简报
晚上 10:00  每日工作总结
晚上 10:00  每周总结 / 每周复盘节点

早上 8 点的任务使用网页和研究工具。晚上 10 点的任务使用会话搜索和带记忆的总结能力，因此 Hermes 可以回顾我实际做过的工作，而不是让我手动重建这一天。

实际用下来，cron 的提示词比日程本身更重要。提示词规定了我关心哪类信息、输出应当多精简，以及哪些工作类别绝不能漏掉。

早上 8 点：每日简报

每天早晨，在开始一天之前，我想要一份简短但有用的概览。

我的每日简报由几部分组成：

  • AI 精选阅读：论文、技术报告、模型发布和重要博客文章。
  • 研究相关性：某篇论文或某次发布为什么对视频生成、VLM、diffusion/flow 模型、多模态 agent 或 3D 生成重要。
  • 市场观察：我关注的 AI 相关公司和板块的宏观走势。
  • 待办事项：一小份今天可以考虑去做的具体事项清单。

关键在于，这份简报不是一份泛泛的新闻摘要，而是按我的研究品味调校的。举个例子，一份普通的 AI 通讯可能只是提到某个新模型发布了。Hermes 会试着回答那个更有用的问题：它是否改变了我应该读什么、写什么、测试什么、思考什么？

我还希望论文部分带上直接的原文链接，尤其是 arXiv 摘要页链接。这让简报可以直接付诸行动：我可以立刻在手机上打开论文，判断它是否值得之后深读。

晚上 10 点：每日与每周总结

晚上 10 点的总结与早上 8 点的简报正好相反。早晨，Hermes 向外看；夜晚，它向回看。

每日总结回答这些问题：

  • 我今天实际做了哪些工作？
  • 哪些论文修改、稿件改动、代码改动或博客草稿是重要的？
  • 我做了哪些决定？
  • 明天应该继续做什么？

这很有用，因为大量研究工作是碎片化的。一天可能包括重写一节论文、打磨一张图、检索一轮相关工作、跑一个代码实验，再加一篇博客草稿。没有总结，这一天会显得零散；有了总结，工作就变成了一条可追溯的轨迹。

每周总结是同一想法的更高层版本。它把每日活动压缩成主题：推进了哪些论文、准备了哪些投稿、调试了哪些实验、完成了哪些写作，以及有哪些待跟进事项。

目标不是为了记日记而记日记。目标是连续性。Hermes 帮助把许多微小的交互变成一份持久的工作记忆。

论文写作与润色

对我来说，最有价值的用例是论文写作。

Hermes 可以直接操作本地论文仓库。这意味着它能查看 LaTeX 文件、编辑章节、润色段落、检查一致性，并在需要时运行构建或搜索命令。

我用它做几类论文工作：

  • 语法与表达润色：在不改变技术含义的前提下清理语言。
  • 相关工作梳理：比较论文、归组引用、改善叙事流畅度。
  • 方法章节重写：在保留技术论断的同时让结构更清晰。
  • 摘要与引言迭代：打磨动机、贡献和定位。
  • 投稿准备：检查文件、图注、参考文献和论文相关的 TODO。

重要的是，Hermes 记得我的偏好。比如，当我要求做语法润色时，我通常不希望它重写整个论证。我希望它修正语法、错别字和别扭的措辞，同时保留我的原意。

这正是持久记忆和技能派上用场的地方。随着时间推移，Hermes 学会了“重写这一节”和“轻度润色这一段”之间的区别。

写博客与技术写作

我也用 Hermes 写博客。

我的博客工作流通常是：

  1. 我写下粗略的笔记或一个核心论点。
  2. Hermes 把它们变成结构化的草稿。
  3. 我要求做语法润色或加强行文。
  4. Hermes 生成一份干净的本地 HTML 或 Markdown 版本。
  5. 发布之前，我人工审阅最终版本。

这对偏推测性的技术文章尤其有用——这类文章的目标不只是正确性，还有定位：论点是什么、各种可能性如何排序、有哪些公开证据，以及哪些论断应该留有余地。

Hermes 尤其擅长帮我让一篇博客保持在正确的“模式”里。有些文章应该精确而技术化；有些应该口语化；有些要按 X 或 LinkedIn 的格式来写；有些则应保持为一份干净的独立 HTML 文件。

用手机远程办公

移动端工作流让这套系统与普通的终端 agent 感觉截然不同。

因为 Hermes 可以通过飞书/Lark 推送消息，我可以在手机上和它交互。这意味着我可以：

  • 不用打开笔记本就收到早上 8 点的简报；
  • 不在书桌前也能查看晚上 10 点的总结；
  • 在路上想起什么时，随手发一条快速指令；
  • 让它在我回到电脑之前先检查或准备好本地工作；
  • 把手机当作研究与写作任务的轻量指挥中心。

这并不能取代笔记本上的深度工作，它消除的是深度工作周围的摩擦。走路、通勤或会议间隙冒出一个想法，我可以直接发给 Hermes；如果某次定时总结提醒我漏掉了一个 TODO，我可以立即回复。agent 成了移动碎片时间与桌面执行之间的桥梁。

实际效果是，我的研究工作流不再绑定在某一个物理场景上。重活仍然由 Mac 承担，但手机成了同一个助手的远程界面。

为什么这很重要

最大的收益是连续性。

研究和写作不是单轮任务。它们在一天又一天中展开：读论文、形成观点、重写章节、更新论断、准备投稿，还要记住昨天改了什么。

Hermes 帮助把这些碎片连接起来。每日简报把新信息带进来；每晚总结把一天压缩下来；每周总结把零散的进展变成更高层次的记录；写作工作流让论文和博客草稿持续推进；移动界面则让这个循环在我不在书桌前时也保持运转。

这就是为什么在我眼里，Hermes 与其说是一个聊天机器人，不如说是一个全天候在线的研究与写作助手。
