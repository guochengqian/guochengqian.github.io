大模型训练的并行策略：基础必备知识你都知道吗？

FSDP、TP、PP、CP 和 EP 是什么区别，它们分别切分什么。

Gordon Guocheng Qian
2026 年 7 月 17 日 · 阅读约 7 分钟
方法切分对象解决的问题

FSDP：切模型状态，不切一层计算

DDP 每张卡都有完整模型，分不同样本，最后 all-reduce 梯度。FSDP 进一步把参数、梯度和优化器状态分片：用某个 FSDP unit 前 all-gather 完整参数，用完再 reshard，反向时 reduce-scatter 梯度。

重点：FSDP 不切该层的 activation，也不把一个 Linear 的矩阵乘拆到多卡。它改变的是模型状态的存储；计算和 activation 仍是完整的一份。DDP 的 gradient bucket 只能在反向产生后通信，因此可和更早层的反向计算重叠。

TP：切一个大 Linear 的 channel

TP 用于一个 layer 本身就太大的情况。它把权重和 channel-direction 的中间 activation 分到多卡，每卡只计算自己的 channel shard；必要时再通信合并。以 MLP 为例，令 T = B × S：

X ∈ ℝT × D, W1 ∈ ℝD × H, W2 ∈ ℝH × D
H = GELU(XW1), Y = HW2
W₁ 按列切：W₁ = [W₁⁽⁰⁾ … W₁⁽ᵗ⁻¹⁾] W₁⁽ⁱ⁾: [D, H/t] W₂ 按行切：W₂ = [W₂⁽⁰⁾; …; W₂⁽ᵗ⁻¹⁾] W₂⁽ⁱ⁾: [H/t, D] GPU i: Hᵢ = GELU(XW₁⁽ⁱ⁾) [T, H/t] 本地计算 GPU i: Yᵢ = HᵢW₂⁽ⁱ⁾ [T, D] 部分输出 Y = ΣᵢYᵢ all-reduce

注意：在 tensor parallel 中，X 在 TP group 内复制；权重 W1、W2 沿 channel 维切开，中间 activation H 也随之切开。也就是说，同一个 TP group 内的每张 device 拿到相同的数据，只做其中一部分计算。Attention 同理：Q/K/V 按 head 切，分别计算本地 head，输出 projection 再合并。

TP 与 FSDP：FSDP 临时聚合完整参数，activation 和 layer computation 不切；TP 始终把一个 layer 的 channel-shard 权重、activation 和计算放在不同 GPU。

PP：按网络深度 block 切分

PP 沿网络深度切：连续的 Transformer blocks 分给不同 stage，每张 device 只保存并计算自己的那段模型。一个 training batch 再切成 M0、M1…等 micro-batch，依次在 stage 间传 activation；反向时 gradient 沿反方向传回。

forward: M₀: stage 0 → stage 1 → stage 2 backward: M₀: stage 0 ← stage 1 ← stage 2 同一时刻：stage 0 可算 M₃，stage 1 可算 M₂，stage 2 可算 M₁。

1F1B：一个新的前向，配一个更早的反向

1F1B 不是同一个 micro-batch 刚前向就立刻反向。它必须先到最后一个 stage 才能产生 loss 和 gradient。它的意思是：流水线填满后，每个 stage 交替处理一个较新的 micro-batch 的 forward和一个较早的 micro-batch 的 backward。

阶段发生什么目的
warm-up只做 forward，把多个 micro-batch 填进流水线。让最后一个 stage 拿到第一个 loss。
steady（1F1B）交替做一个 F 和一个 B，例如 F(M4)、B(M1)、F(M5)、B(M2)。保持设备忙碌，同时不必保留所有 micro-batch 的 activation。
cool-down不再注入新的 micro-batch，只完成剩余的 backward。排空流水线并累积完这一 batch 的梯度。

灰色空档就是 pipeline bubble：开头还没填满、结尾已没有新的 forward 可做。micro-batch 越多，bubble 占比越小；但调度和 stage 间通信会增加。GPipe 的 flush 调度是先完成所有 forward、再做所有 backward，简单但要保留更多 activation；1F1B 更省 activation。

Interleaved 1F1B：一张卡持有多个 virtual stage

图中的 3 个 physical stage 又各拆成 2 个 model chunk，共 6 个 logical stage。以 device 0 为例，它持有 chunk 0 和 chunk 3；一个 micro-batch 的 forward 路径是 device 0 → 1 → 2 → 0 → 1 → 2。这样把流水线切得更细，减少 bubble，但会增加 stage 间传输和调度复杂度。

CP / SP：按 token 切序列

逐 token 的操作可本地做；attention 难在每个 query 需要全序列 K/V。最简单的方案是 all-gather K/V。Ring Attention 则固定本地 query，让 K/V block 在环上流动，以 online softmax 累积精确 attention。

Ulysses 是另一种布局：从 [sequence shard, all heads] 经 all-to-all 变成 [full sequence, head shard]，本地完成 attention 后再 all-to-all 变回去。它交换的是切分轴；Ring Attention 则流式传递 K/V。

EP：按 expert 切 MoE

每张卡保存完整 expert，router 把 token 经 all-to-all 发往被选中的 expert，再 all-to-all 返回输出。容量随 expert 数增加，但每个 token 只激活 top-k 个 expert；瓶颈是路由失衡。

组合

FSDP/DP × TP × PP × CP/SP × EP。常见做法是把通信最频繁的 TP 放在 NVLink/NVSwitch 岛内，用 FSDP/DP 跨节点扩展副本，再按需要加入 PP、CP 和 EP。
