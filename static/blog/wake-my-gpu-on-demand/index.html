A Visual Generation Practitioner’s Three Machines

A roaming laptop, a Mac mini running my agents around the clock, and an RTX 5090 that sleeps until something wakes it in 30 seconds.

Gordon Guocheng Qian
July 8, 2026 · 2 min read

Three machines, three jobs

I work across three machines, and each exists because the other two cannot do its job.

The MacBook Pro is where I actually work. It travels: home, office, café, plane. Its network changes several times a day, which means nothing else in the setup can rely on knowing where it is.

The Mac mini never sleeps. It runs my Hermes, Codex, and Claude agents around the clock — the 8am briefing, the 10pm summary, the jobs that fire while I am asleep or on a plane. So this machine is always on. That is its real job.

The Ubuntu workstation has an RTX 5090 in it. I use it a few times a week. The rest of the time it should be asleep, not idling. So it sleeps by default and wakes only when it is needed.

How they connect

All three sit on one Tailscale network, so every machine has a stable address that follows it across Wi-Fi networks. That solves the roaming laptop entirely: from a café, it reaches the workstation as if it were on the same desk.

But Tailscale cannot reach a machine that is asleep, because a sleeping machine is not on the network at all. The only thing that wakes it is a magic packet — a Wake-on-LAN broadcast that lives at the link layer. It cannot be routed across the internet. It has to be shouted on the workstation’s own LAN, by something already sitting there.

The Mac mini is already sitting there, already on, for the agent. So waking the GPU costs nothing extra: it is a second job for a machine that was never going to sleep anyway. That is the whole reason the setup needs exactly three machines and not two.

Note what does not go through the Mac mini. Running a job, checking GPU usage, suspending the box afterwards — all of that is the laptop talking directly to the workstation over Tailscale, from any network. Only the wake needs a relay.
