模型 Scaling 之后，下一个 Scaling 是什么？

对日常用户来说，ChatGPT、Claude 这类顶级聊天机器人的知识层已经足以胜任许多工作。下一个产品前沿是更便宜、更快、更 agentic 的自动化 — 也就是 context scaling 和 agent scaling。两者都需要显著更多的内存带宽（memory bandwidth），这意味着 HBM 短缺远未结束。

Gordon Guocheng Qian
2026 年 6 月 22 日 · 阅读约 9 分钟

对大多数日常用户来说，ChatGPT、Claude 这类产品的基础知识和推理能力，已经足以应付许多日常任务：回答问题、写代码、总结文档、规划行程、起草邮件、讲解概念。当这种能力成为常态之后，用户尚未被满足的需求就从“懂得更多”转向了“替我做更多”。杠精会说，我们只是需要更多参数罢了。XD

Context scaling

如今的 tier-0 模型出厂就带着约 1M token 的 context 窗口。这足够你上传一整本书、就书中内容提问、跑一次网络搜索，再把所有信息汇总起来，生成一份详尽的回答。

但如果你不停地上传书籍、不停地附加图片、不停地搜索互联网、在一个长会话里不停地和聊天机器人对话 — 迟早会撞上上限。context 被填满，较早的信息被逐出或压缩，模型的输出质量随之下降。这是继续 scale context 最显而易见的理由。

但还有一个更深层的理由，而且更加重要。

Context 是梯度下降之外的另一条路。

这句话出自 Andrej Karpathy 与 Dwarkesh Patel 的对谈。更深层的含义在于：context 窗口不只是一个长期记忆的缓冲区，它还给了模型另一种在推理时进行适应的方式。

严谨的说法并不是模型的权重在推理时发生了变化 — 权重并没有变。关键在于，context 可以扮演一种临时学习基质的角色：示例、检索到的文档、笔记、测试、计划、工具输出、失败记录，全都变成了在前向传播过程中改变模型行为的状态。

这与 Jiayi Weng 的《Learning Beyond Gradients》相呼应：一个 coding agent 可以不断读取失败信息、修改代码、补充测试、回看执行记录，在不训练任何新神经网络的情况下持续改进一个软件系统。被更新的对象是显式且可维护的 — 规则、测试、日志、memory、版本 diff、反馈渠道 — 而不只是隐藏的权重。

虽然 in-context learning 本质上是高级的模式补全，但在机制上，它可能像一个在网络前向传播过程中运行的小型内部梯度下降循环。
— Andrej Karpathy

递归自我改进也许根本不需要训练 — 只需要 In-Context Manipulation。一个能写入自己 context 的 agent — 笔记、计划、过往错误、发现的启发式、子目标、中间推理 — 实际上可以在推理时“微调”自己，而不触碰任何一个权重。context 越大、越结构化，这个自我改进的循环就越强大。

定制化不需要训练 — 只需要更大的 context。

这也是为什么更大的 context 窗口对企业级和个性化 LLM 如此重要。你不必为每个客户单独微调一个模型，而是可以让同一个强模型基于一份丰富、持久的 context 来工作：用户偏好、公司知识库、交互历史、领域专属指令。个性化从一个训练问题，变成了一个 context 工程问题。

Agent scaling

第二个 scaling 维度是 agent 数量。

这已经是市场正在走的方向。顶级聊天机器人公司不只是在发布更大的旗舰模型，还在推出更便宜、更快的模型，并把它们包装成更 agentic 的产品：coding agent、deep research、computer-use agent、工作流自动化、任务执行。趋势很清楚：大多数用户对模型的原始能力已经越来越满意，但他们想要更多的自动化。

token 数据也指向同一个方向。随着模型变得更便宜、更有用，市场消耗的并不是多一点点推理量，而是多出几个数量级的 token — 先是通过 chat 和 API 的使用，随后是通过那些在循环中阅读、搜索、规划、调用工具、验证输出、不断重试的 agent。

当前的 agent 系统仍处于早期：一个模型、一份 context、一条动作流。

Cathie Wood 和 ARK Invest 在他们的《Big Ideas 2026》报告中提出了类似的观点。他们把基础模型描述为互联网技术栈中的一个新层：用户将越来越少地通过点击各种 app 来交互，而是把目标委托给 AI agent，由它们代为搜索、比价、下单和交易。在他们的框架里，agent 会变成一种消费者操作系统。

现在想象一下未来某个版本的 ChatGPT 或 Claude Code：你可以同时启动 100 个甚至 1,000 个 agent — 每一个都在自己的领域具备超人级智能，每一个都有自己的 context，并行运行，通过共享 memory 或消息传递来协同。

  • 一个 agent 读代码库；另一个写测试；另一个 review diff；另一个负责部署；另一个监控日志。
  • 一个 agent 检索文献；另一个跑实验；另一个写论文；另一个管理引用。
  • 一个 agent 盯着你的投资组合；另一个扫描财报文件；另一个执行交易；另一个负责风控。

算力需求并不随 agent 数量线性增长 — 它随 agent 数量 × context 长度 × 协同开销一起增长。一个每个 agent 都维持 1M token context 的 100-agent 系统，与单个聊天机器人相比，是完全不同量级的计算形态。

两者都需要多得多的 HBM — 以及更多的 AI 基础设施

硬件层面的现实是这样的：

  • Context scaling 意味着 KV cache 随 context 长度线性增长。在一个 10T 参数的模型上，1M token 的 context 光是存放激活值就需要巨大的内存。要做到 10M 甚至 100M token，需要的不只是更大的 context — 而是每张 GPU 上更大的内存，以及更多的 GPU。
  • Agent scaling 意味着并行运行大量独立的模型实例，每个实例都有自己的 KV cache。1,000 个 agent × 每个 1M token，就是 10 亿 token 的活跃 context 必须常驻在高速内存里。

这两者首先都是内存带宽受限、内存容量受限的问题。而一旦 context 和 agent 的规模起来了，需求不会止步于 HBM，还会外溢到定制推理芯片、scale-out 网络、scale-up 互连、光模块 DSP，以及全栈 GPU 系统。

所以这个投资逻辑很简单：

模型 scaling 驱动了上一波 GPU 需求。context scaling 和 agent scaling 将驱动下一波对内存、网络、定制 ASIC、光互连和全栈 AI 基础设施的需求。

总结

模型 scaling 仍然重要。但对日常用户来说，实际的瓶颈正在转移：聊天机器人懂得的知识已经足够应付许多任务，而产品替用户做的事仍然太少。

Context scaling 是下一条 scaling law，因为 context 可以充当推理时的学习基质 — 不是通过更新权重，而是携带示例、memory、测试和反馈，在推理过程中改变模型的行为。

Agent scaling 是显而易见的下一步：从一次聊天回复，走向成百上千个自动化动作，每个动作由更便宜、更快、更专精的 agent 并行完成。

两者都需要多得多的内存，以及围绕模型的多得多的基础设施。瓶颈正从纯粹的 FLOPS 转向 HBM 带宽与容量、推理 ASIC、网络、光互连和 scale-up 系统。所以这篇博客的结论很简单：

多买点 SK 海力士和美光。😂

这并不完全是玩笑。在 context scaling + agent scaling 这套逻辑里，内存 / HBM 是最上游的约束，而领先者很清晰：SK 海力士是 HBM 龙头，份额约 50–60%；美光是美股中表达 HBM / DRAM 逻辑最纯粹的标的，在 HBM 上争夺第二或第三的位置，并且在 DRAM 上最近超越了三星；三星是第三大 HBM 玩家。

但受益者版图比 HBM 更广。按品类来看，各领域的领先者如下：

  • 内存 / HBM：SK 海力士是 context + agent scaling 技术栈最上游的领先者，HBM 份额约 50–60%。美光是美股中表达 HBM / DRAM 逻辑最纯粹的方式：HBM 第二或第三，DRAM 最近领先于三星。三星是第三大 HBM 玩家。
  • 定制 ASIC / XPU：这是推理和 agent 算力的第二波。博通（Broadcom）是领先者，在定制 AI 加速器芯片中占有约 70% 的份额；迈威尔（Marvell）是第二大玩家，约 25%。博通的 AI 业务正在极速扩张：FY2026 第一季度的 AI 收入约 84 亿美元，同比增长 106%；AI 芯片毛利率约 65%；FY2026 的 AI 收入目标约 560 亿美元，在手订单约 730 亿美元，2027 年的目标接近 1,000 亿美元。据报道，其 XPU 客户名单包括 Google、Meta、OpenAI、Anthropic、Apple，可能还有字节跳动。
  • AI 网络交换芯片：博通同样是这里的领先者。Tomahawk 6 是业界首款 102.4 Tbps 以太网交换芯片，Jericho 4 则把 fabric 层延伸到了超大规模 AI 集群。
  • 光互连 / 光模块 DSP：迈威尔在光 DSP 这一层领先。其 PAM4 DSP 是 800G 和 1.6T 光模块背后的行业标准，而随着 scale-out AI 集群不断扩张，光模块的重要性还会继续上升。
  • 商用以太网交换机系统：Arista 是系统级的领先者。在底层，这些交换机中的许多仍然依赖博通的芯片，而 NVIDIA 的 Spectrum-X 正在激进地争夺 AI 以太网这块市场。
  • GPU / 全栈 AI 计算：NVIDIA 仍是全栈领先者，AI 芯片份额约 70%。凭借 Vera + NVLink，它不仅是 GPU 的领先者，也在引领 agent-CPU 与 scale-up 互连这一层。
